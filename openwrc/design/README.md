# Design Documentation

This directory contains design documents explaining architectural decisions and data model reasoning.

## Documents

- **[result-models-design.md](./result-models-design.md)** - Design decisions for result/timing data models, including denormalization strategy, query patterns, and API discoveries

## Purpose

Design docs serve as:
- **Decision records**: Why certain approaches were chosen
- **Context for contributors**: Understanding the reasoning behind the current implementation
- **Reference during refactoring**: Ensuring changes maintain the original design goals

## When to Add Design Docs

Create design docs when:
- Making non-obvious architectural decisions
- Choosing between multiple valid approaches with trade-offs
- Discovering important API/data structure patterns
- Implementing complex query optimization strategies
